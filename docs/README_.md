## 1. 实验背景
  
GUI Agent 通过截图观察页面，让多模态模型决定下一步，再执行点击、输入或滑动。它可以通过界面完成操作，不要求每个目标 App 都提供业务 API。

</p>
  
其中，**Planner** 负责规划，**Decider** 负责看图决策，**Host** 是接收指令和展示结果的助手 App。**Self-HDC** 指 App 连接本机调试服务执行设备操作；课程设备上运行时无需电脑代为点击，但模型请求仍需要可达的模型服务。**HAP** 是应用安装包。
  
本实验从已有 HarmonyOS 工程出发，先完成 OH 适配，再验证搜索、写入、跨 App 查询和下载。设备执行模块可以复用，重点是接通完整任务流程，并通过实际结果判断任务是否完成。
  
## 2. 实验目标
  
将课程提供的 HarmonyOS App 迁移到 OpenHarmony（以下简称 OH），实现一个能接收自然语言指令、操作其他 App 并返回结果的智能助手。
  
完成实验后，你的 App 应能：
  
- 在指定 OH 设备上安装、启动并接收中文指令。
- 搜索资料，返回可核对的内容和来源。
- 将指定文字写入备忘录并保存。
- 根据一条指令自动切换多个 App，完成查询和记录，最后返回助手。
- 下载指定文件，显示下载结果和保存位置。
  
实验建议用时 4 小时。按下面的顺序完成必做任务，有余力再做拓展题。可以使用 AI 编程助手辅助阅读代码、修改和排错，每次修改后都要在设备上验证。
  
## 3. 实验环境与课前准备
  
### 3.1 硬件与软件
  
| 项目 | 要求 |
| --- | --- |
| 开发板 | 使用课程镜像和已配置的 Self-HDC 执行环境；参考设备的调试 shell 为 root |
| 开发电脑 | 安装课程配套的 DevEco Studio、OpenHarmony SDK、Hvigor 和依赖工具 |
| 设备连接 | USB 调试可用，电脑能够执行 `hdc` 命令 |
| 模型服务 | Planner 可用文本模型；Decider 需要支持图片输入的多模态模型 |
| 目标 App | 浏览器、备忘录可以手动打开并完成搜索、保存等基本操作 |
| 测试资料 | 一份可下载的中文文本、有效与无效下载链接 |
| 中文输入 | 准备可用的中文输入法或键盘输入方案 |
  
SDK 与构建工具使用课程指定的配套版本。当前 OH 参考工程的编译版本为 API 23、最低兼容版本为 API 18；调用接口时仍需检查目标设备是否支持。
  
### 3.2 设备检查
  
在电脑终端执行以下命令，先确认只连接了一台实验设备：
  
```sh
hdc list targets
hdc shell id
hdc shell 'command -v aa && command -v bm && command -v snapshot_display && command -v uitest && command -v base64'
hdc shell 'uitest uiInput help'
hdc shell 'netstat -lnt'
```
  
检查结果应包括设备标识、调试 shell 身份、各命令路径、触控命令帮助，以及课程配置的 Self-HDC 监听端口，默认使用 `8710`。若存在多个连接，后续命令用 `hdc -t <设备标识>` 指定目标。
  
对 App 而言，`127.0.0.1` 是开发板本身。Self-HDC 需要本机 `hdcd` 开启 TCP 监听；电脑能够通过 USB 连接设备，并不代表 App 已能连接 Self-HDC。未通过检查时，请助教按[设备配置说明](HDC_SELF_CONTROL.md )处理。
  
### 3.3 工程与服务检查
  
1. 运行 HarmonyOS 源 App，熟悉输入、发送、任务状态和设置页面，保存源代码副本。
2. 导入工程并安装依赖，确认签名配置与实验设备匹配。
3. 填写模型服务地址、模型名和密钥，从开发板实际发送一次请求，确认响应正常。
4. 手动完成一次浏览器搜索、备忘录保存和测试文件下载。
  
模型服务部署在电脑上时，App 应使用开发板能够访问的电脑地址，不能填写开发板的 `127.0.0.1`。
  
阅读参考代码时，可以先看[任务循环](../entry/src/main/ets/core/AgentRunner.ets )、[设备执行入口](../entry/src/main/ets/core/PhoneBridge.ets )和[应用目录](../entry/src/main/ets/core/AppCatalog.ets )。新增浏览器等目标 App 时，核对设备上实际安装的包名和入口。
  
### 3.4 模型服务不可用时
  
可以接入课程测试服务，以预设响应验证请求、动作执行、取消和错误处理。测试服务也需要能从开发板访问。预设动作不会随真实画面自动调整，使用时记录测试条件；搜索和跨 App 等完整任务最终使用真实模型服务验收。
  
## 4. 操作步骤与验收标准
  
> 本阶段**禁止**直接复制参考仓库文件到你的工程。允许阅读，允许让 AI 帮你解释，不允许整文件搬运。
  
### 第一步：把 HarmonyOS App 迁移到 OH
  
**操作步骤**
  
1. 运行源 App，了解输入、发送、任务状态和设置入口，保留一份源代码副本。
2. 检查构建配置、SDK、依赖和权限，按课程指定的 OH 环境调整工程；逐项处理不兼容的接口。
3. 编译、签名并安装到 OH 设备，检查主页面、中文输入和模型服务连接。
  
**验收标准**
  
- 生成可安装的 HAP，App 冷启动正常，能输入并发送中文指令。
- 模型请求能得到响应；连接失败时有提示，恢复配置后可以重试。
- 能结合代码说明至少一处平台适配及其原因。
  
### 第二步：完成搜索
  
**操作步骤**
  
1. 接入浏览器启动、输入关键词和读取结果的流程。
2. 输入“搜索 OpenHarmony 入门资料”，让助手打开浏览器、完成搜索并返回结果。
3. 更换关键词再试一次，检查结果是否随输入变化。
  
**验收标准**
  
- 无需手动在浏览器输入关键词，能看到与指令对应的真实搜索结果。
- 助手返回至少一条结果的标题、简要内容和来源链接，内容与页面一致。
- 搜索无结果或网络失败时能说明情况，并允许重新发起任务。
  
### 第三步：完成写入
  
**操作步骤**
  
1. 接入备忘录的打开、新建、文字输入和保存流程。
2. 输入“在备忘录中新建‘OH 实验记录’，写入‘今天完成了应用迁移和搜索测试’并保存”。
3. 关闭并重新打开备忘录，检查记录是否保留。
  
**验收标准**
  
- 备忘录中实际生成指定标题和正文，中文内容完整。
- 退出并重新打开后仍能找到记录。
- 助手的完成提示与实际保存结果一致。
  
### 第四步：完成跨 App 自动跳转查询
  
**操作步骤**
  
1. 把搜索和写入串成一个任务：接收指令后，依次打开目标 App、读取结果、切换 App、写入保存，再返回助手。
2. 测试指令：“搜索 OpenHarmony 入门资料，选一条结果，把标题、链接和一句简介保存到备忘录‘OH 学习资料’。”
3. 显示当前执行步骤与最终结果，并提供停止按钮；运行过程中测试一次停止操作。
  
**验收标准**
  
- 一条指令触发浏览器和备忘录两个 App 的连续操作，过程中无需手动切换或复制粘贴。
- 保存的内容来自本次搜索，标题、链接和简介可以与原页面核对。
- 任务结束后返回助手并展示结果；失败时能指出中断步骤。
- 点击停止后不再执行新动作，任务显示为已取消。
  
### 第五步：完成文件下载
  
**操作步骤**
  
1. 使用课程提供的测试链接，输入“下载这个文件”，由助手打开链接并发起下载。
2. 显示下载状态，完成后展示文件名和保存位置。
3. 检查文件内容，再使用无效链接验证失败提示。
  
**验收标准**
  
- 文件真实保存到设备，可以通过 App、文件管理器或调试工具定位并打开核对。
- 文件名、大小和内容与测试文件一致，中文文本没有乱码。
- 下载完成后才显示成功；无效链接或网络中断时显示失败，能够重试。
  
### 第六步：整体验收
  
按“启动助手 → 搜索 → 写入 → 跨 App 查询与记录 → 下载文件”的顺序演示一遍，再演示一次任务停止或失败恢复。
  
最终提交：
  
- 源码和可安装的 HAP。
- 一段约 3 分钟的实机演示，覆盖上述必做功能。
- 简短实验记录：运行环境、主要适配点、各项验收结果；如有未通过项，说明现象和原因。
  
## 5. Vibe Coding 工作规范
  
使用 AI 编程助手时，按“提出一个小目标 → 修改 → 编译或运行 → 核对结果”的顺序推进。
  
1. **小步提交**：每完成一个功能提交一次代码，说明修改内容和验证结果。
2. **先读再改**：让 AI 先解释相关代码和修改范围；新增模块时先确认接口与输入输出。
3. **提供有效报错**：保留首个有效错误、相关代码、环境信息和期望行为，让 AI 解释原因后再修改。
4. **复核生成代码**：能说明关键代码的输入、输出、失败处理，以及为什么适用于当前 OH 设备。
5. **保留代表性记录**：选两次有价值的 AI 协作过程，简述建议、你的判断与实际验证结果。
6. **保护配置**：密钥放在本地配置中并排除提交；截图、日志和演示中不展示完整密钥。
  
遇到自动化故障时，按“设备连接 → 截图与动作 → 模型响应与解析 → 任务循环与收尾 → 界面展示”的顺序定位。先确认最小操作可用，再测试长任务。
  
## 6. 拓展题：为 Agent 接入更多 App（携程 / 淘宝等，选做）
  
### 6.1 任务说明
  
截图点击适合操作现有界面；需要精确筛选、批量读取或跨 App 比较时，可以尝试 API、SDK 或工具服务。选择一个场景，例如查询酒店、商品或出行信息，让 Agent 根据任务选择合适的调用方式。
  
先确认目标 App 能在所选设备上运行，或其服务提供可申请使用的官方接口。携程、淘宝是选题示例，具体可做范围以实际获得的接口、账号和设备条件为准。
  
### 6.2 三个方向
  
**方向 A：API / SDK 与公开跳转入口**
  
- 通过官方开放 API 或适配目标平台的 SDK，封装一个查询工具，约定名称、参数和返回结果。
- 也可以通过目标 App 支持的链接、URI 或分享入口，打开指定页面并携带参数，再继续界面操作。
- 例如实现“查询指定城市和日期的酒店，返回若干结果”。能否读取结果取决于实际接口；页面跳转只证明进入了页面。
  
**验收：** 完成一次真实调用，结果可以核对；说明哪些步骤使用 API、哪些步骤使用界面操作，并处理调用失败。
  
**方向 B：MCP 工具服务**
  
MCP（Model Context Protocol）用于让模型应用发现和调用外部工具。可以在电脑或服务器部署工具服务，提供 `search_hotel(city, checkin, checkout)` 等能力。
  
- 先确认数据来源和接口，再封装工具；定义函数名本身不会产生商用服务查询能力。
- App 可以通过课程提供或自行实现的 HTTP 网关发起调用，由网关连接 MCP 服务。
- 将可用工具及参数告诉模型，执行工具调用后把结果交回模型，用于继续回答或操作。
  
**验收：** 演示一次真实工具调用，展示参数、返回结果及其在后续任务中的使用；服务不可用时给出明确提示。
  
**方向 C：混合规划器**
  
- 在 Planner 阶段判断使用 GUI 还是 API / 工具服务，或让 Decider 在执行过程中选择调用工具。
- 为至少两类任务设置路由，例如资料查询使用工具，备忘录记录使用 GUI。
- 工具失败时，可以在设备能力允许的情况下转向 GUI；无法继续时说明原因并结束任务。
  
**验收：** 演示两种执行路径和一次失败处理，能解释每次选择的依据。
  
### 6.3 提交与比较
  
任选一个方向，提交实现代码、一次实机演示，以及简短说明：工具的参数和返回值、实际数据来源、失败处理方式。
  
如果同一任务可以分别通过 GUI 和工具完成，可各运行 3–5 次，记录步骤数、耗时和成功次数，解释适用场景。使用测试数据时标明来源；演示以查询为主，不绕过登录和访问限制。
  
## 7. 常见问题（FAQ）
  
**Q1：安装 HAP 时提示签名不匹配？**
  
先核对已安装 App 与新 HAP 的包名、证书和签名配置。覆盖安装应使用匹配签名；需保留原 App 时使用分配的新包名，避免直接卸载造成数据丢失。
  
**Q2：电脑能连设备，App 却连不上 `127.0.0.1:8710`？**
  
USB 调试和本机 TCP 连接是两条通路。检查 `hdcd` 的 TCP 监听端口、App 中的地址与端口，以及设备授权。端口未监听时请助教检查设备配置；认证失败时保留具体错误信息。
  
**Q3：截图黑屏、内容不完整或点击位置不对？**
  
先打开原始截图检查目标画面能否正常显示和解码，再核对屏幕方向、物理分辨率与动作坐标。模型看到的缩略图尺寸可能与实际屏幕不同。命令出现警告文本时，结合执行结果和实际图片判断。
  
**Q4：中文输入乱码，或者外接键盘只能输入英文？**
  
自动输入乱码先检查文本编码、命令引号和特殊字符转义；手动拼音输入需要设备安装中文输入法并完成切换。这两种问题分开排查。
  
**Q5：模型返回代码块或不完整 JSON，解析失败？**
  
记录原始响应，先去除代码块包装，再按动作结构校验必需字段、参数和取值。解析失败时重试或报告错误；不要执行猜测补出的动作。可以参考已有解析模块处理响应。
  
**Q6：App 切到后台后任务停止？**
  
检查后台任务申请结果和临时运行额度。额度到期时应停止后续操作并展示原因；核对日志中的后台任务状态，不要把中断显示成完成。
  
**Q7：任务结束后回不到助手？**
  
检查返回入口、包名和任务清理顺序。课程 Self-HDC 执行环境可参考已有返回逻辑；原连接已关闭时，检查是否建立了用于返回的新连接。返回失败应记录日志，保留原任务结果。
  
**Q8：能打开浏览器，但搜索或跨 App 查询无法完成？**
  
先手动确认搜索可用，再检查应用目录、模型响应和失败步骤。把任务拆成“搜索并读取结果”和“写入备忘录”分别验证，确认前一步的标题、链接等数据实际传到了后一步。
  
**Q9：显示下载成功，却找不到文件？**
  
检查下载回调、实际写入结果和保存路径，确认是否保存在浏览器私有目录。只有文件落盘后才报告完成；需要导出时再提供相应入口，私有目录中的文件不一定出现在文件管理器里。
  
**Q10：模型请求连接失败或一直等待？**
  
核对服务地址、密钥、模型名和设备网络，区分连接失败、鉴权失败与响应超时。电脑能访问服务不代表开发板也能访问。重试前恢复界面状态，点击停止后不再执行迟到响应中的动作。
