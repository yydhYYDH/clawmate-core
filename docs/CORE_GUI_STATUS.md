# 基础 GUI 助手改造与验收

## 已实现

- 成功、失败、暂停、取消独立处理。只有 `done` 且显式成功状态才显示完成。
- 初始化也受到 `finally` 保护；退出时停止云端请求、释放 HDC 和后台任务，并尝试返回聊天页。
- 取消云端等待会主动结束 Promise，即使底层 `destroy()` 不回调也能收尾。单次模型请求上限 90 秒，任务上限 10 分钟。
- Planner 与系统应用名称解析共用 OpenHarmony 应用目录；保留显式包名优先规则。
- 每个任务独立保存正文、技术日志和运行状态。日志默认折叠、浅色显示，折叠时仍持续更新；正文同时追加。
- 每次成功执行动作后输出中文操作回执。下一轮截图决策可通过 `progress` 返回可见成果；最终可通过 `summary` 返回结果。
- 操作回执与截图确认分开：点击成功不会直接宣称业务完成。不返回 `progress`/`summary` 的模型仍有本地回执和最终状态。
- 最新正文后显示当前阶段计时；超过 30 秒无事件会显示等待提示。终止后固定总耗时。界面最多保留最近 400 条日志，hilog 仍接收完整过程。
- 输入框保持普通文本类型；提供系统输入法选择框和当前输入法名称。按用户要求移除输入框旁的「系统设置」按钮。
- 聊天正文和展开的日志可划词/长按选择并通过 Ctrl+C 复制到系统剪贴板；输入框支持 Ctrl+V 粘贴。选择正文时暂停自动跟随输出，避免复制期间滚动。
- 任务结束后自动返回 ClawMate；后台 `startAbility` 被拒绝时，通过独立 self-HDC 连接执行宿主 `aa start`，包括原任务连接已因取消关闭的情况。返回失败只记日志，不覆盖任务结果。
- 任务结束返回后，顶部以浮层滑入任务结束提示，覆盖少量页面区域，不挤动聊天内容，也不拦截点击；显示 2 秒后自动滑出。仅成功显示绿色「任务已完成」；失败、暂停、取消分别标注。新任务开始或页面退出时清理提示计时器，任务结果仍保留在聊天正文。

2026-10-13 补充实机排查：`/proc/bus/input/devices` 和
`hidumper -s MultimodalInput -a -l` 均能识别 Logitech USB Keyboard；
`hidumper -s InputMethodService -a -a` 仅列出当前输入法
`com.example.kikakeyboard/ServiceExtAbility`（kikaInput，版本 1.1.10）。
读取预装 `/system/app/com.example.kikakeyboard/kikaInput.hap` 并用 SDK
`ark_disasm` 检查实体键盘处理：`KeyboardController.onKeyDown` 将按键和 Shift
状态交给 `HardKeyUtils.GetHardKeyValue`，后者按英文字符表映射，Shift + 字母调用
`toUpperCase`；单独的左右 Shift 在 `shiftKeys` 中被识别并跳过文本插入。
该路径没有中英文模式切换或拼音候选处理，因此当前外接键盘无法用 Shift 切到中文。
应用输入框使用 `InputType.Normal`，没有自定义按键拦截。

删除「系统设置」按钮后已重新编译、签名并覆盖安装成功；启动后的 UI 布局回读确认

目前验证的是中文字符串能被聊天框接收，以及 Agent 使用的命令能写入中文。

## 重复验证

1. 在 DevEco 配置与已有应用匹配的签名后，构建并安装。
2. 点击“切换输入法”，选择已安装输入法。
3. 输入“打开计算器”，确认正文独立更新；运行期间展开、折叠日志。
4. 输入需要多个动作的任务，确认每个已执行动作都有回执，等待期间计时更新；停止后不再执行新动作。
5. 检查失败/暂停状态，不应出现“已完成”。

普通聊天问答、画像、收藏、推荐、定时工作流不在此次改造范围内。
