## 一、输入与边界

当前目录就是独立 starter 工程；它已有资料问答、图片/文本导入、本地笔记、设置、取消与超时，以及 `DeviceExecutor` 接口和依赖电脑 HTTP 调试桥的执行器。请先阅读 README、代码地图、平台接口、任务循环、设置与生命周期。保留这些已有用户功能，将设备任务默认实现换为 OH 本机控制。

目标环境：SysLong RoboPi 或课程同类开发板，OpenHarmony 5.1 / API 18，ArkTS Stage 模型。当前课程工具链可用 OpenHarmony API 23 编译，最低兼容 API 18。先检查实际安装 SDK；不能把编译 API 23 当成目标设备 API 23，也不能直接用 HarmonyOS API 20/26 的运行能力。`runtimeOS` 应为 `OpenHarmony`，设备类型按板端支持配置（课程板通常为 `default`）。检查权限、syscap、模型、依赖及签名。

课前条件：设备上有可手动使用的浏览器、备忘录，调试服务支持课程 Self-HDC，模型服务可达。参考包名仅作为探测候选：备忘录 `com.ohos.note`，计算器 `ohos.samples.distributedcalc`，课程独立浏览器 `com.clawmate.browser`；必须用设备元数据核实 Ability，不要假定任何 App 都叫 `EntryAbility`，不要把华为零售浏览器包名当成开发板浏览器。缺少目标 App 时列为环境阻塞，继续其他独立功能。

模型配置通过界面或本地配置提供，不在新增源码、日志或报告中复制密钥。服务在电脑上时，使用开发板可达的电脑地址；`127.0.0.1` 对 App 是板子自身。保留已有模型配置能力；Planner/Decider 可以共用一个支持图片的 OpenAI 兼容模型，也可以分开配置，不能强制依赖不可用的服务。

## 二、必须达到的用户行为

1. **启动与对话**：可构建、签名、安装、冷启动；可输入中文、发送任务、复制回复。聊天正文展示简短中文进展和最终结果，技术日志可折叠。设置可配置模型与 Self-HDC 地址/端口。失败后恢复输入，能够重试。
2. **基础设备控制**：在设备上真正打开指定应用、获取当前跨 App 截图、点击、滑动、替换/追加中文输入、回车、返回、Home、等待及跨 App 启动。先通过“打开计算器计算 12×34”验证链路，结果应为 408；截图确认后才报告完成，随后自动返回助手。
3. **浏览器搜索**：指令“搜索 OpenHarmony 入门资料”。自动打开浏览器并输入查询，返回至少一条实际可见结果的标题、简要内容和来源。更换关键词必须改变实际查询；网址不可见时继续查找或说明无法确认，不能编造来源或声称通过该项验收。
4. **备忘录写入**：指令“在备忘录中新建‘OH 实验记录’，写入‘今天完成了应用迁移和搜索测试’并保存”。真正操作独立备忘录 App，退出重开后标题与中文正文仍存在。助手自己已有的本地笔记不能代替这项验收。
5. **跨 App 查询并记录**：指令“搜索 OpenHarmony 入门资料，选一条结果，把标题、链接和一句简介保存到备忘录‘OH 学习资料’。”一个任务连续执行浏览器查询→提取本次结果→切换备忘录→写入保存→返回助手。任务上下文必须保留实际观察到的信息，不能只传动作名称导致后一 App 丢失标题和链接。全过程无需人工切 App 或复制粘贴。
6. **下载**：对用户给出的有效 HTTP(S) 文件链接，打开浏览器发起下载，展示真实下载状态、文件名与保存位置。完成后核对文件存在、大小、中文内容，最好记录 SHA-256。使用无效链接、404 和中断验证失败与重试。打开链接、点击下载按钮、模型说 done 都不足以认定落盘成功。浏览器私有路径可接受，但应能通过文件管理器、浏览器或调试工具定位核对。若现有浏览器不支持下载，应明确能力缺口；不能悄悄改成只下载到助手沙箱后声称浏览器任务通过。
7. **保留源功能**：资料问答仍提交实际文本/图片数据；支持 UTF-8 `.txt/.md`、BOM、空文件、非法编码/超限失败、取消选择、确认导入、预览及发送前移除附件。保留文本 256 KiB、原图 10 MiB、模型预览长边 1024 的限制。保存的本地笔记及引用资料重启恢复，不误删其他笔记仍引用的文件。完整聊天会话持久化不是本次要求。

## 三、设备执行必须在 OH 本机完成

运行链路应为：助手 App → TCP `127.0.0.1:8710`（可配置）→ 板端 `hdcd` → 系统截图/输入/应用命令。电脑可以用于编译、安装和验收，正式运行时不由电脑 HTTP 桥代为操作。简单把原 HTTP 桥地址改为 loopback 不能实现 Self-HDC。

通过 `DeviceExecutor` 接口接入 `OpenHarmonySelfHdcExecutor` 或等价模块。实现 open、startApp、screenshot、execute、cancel、returnHost、close；业务任务循环不要直接拼调试命令。若教师提供通用 Self-HDC 支持包，可复用并标明来源；未提供时根据公开 OpenHarmony `developtools_hdc` 协议与 SDK 实现，不能引用另一个完整助手 App。

必须处理真实 HDC 设备端二进制协议及握手/认证、TCP 拆包/粘包、输出分片、通道结束、连接/命令超时、取消释放、认证失败诊断。该端口不是 HTTP 服务，也不是电脑侧 HDC server。不能仅发送明文 shell 字符串。认证按课程设备实际机制实现；未获授权时明确报错，不绕过认证或返回假成功。

设备准备先做只读检查：设备列表、系统 API、`id`、`aa`、`bm`、`snapshot_display`、`uitest`、`base64`、TCP 监听，以及浏览器/备忘录元数据。设备配置由教师课前准备，本任务不自行重启设备、修改全局参数、卸载旧 App 或清除数据。

具体行为约束：

- 使用 `bm dump -n <bundle>` 等设备元数据解析入口，通过 `aa start` 启动；只允许目录内且实际安装的目标 App。Planner 与执行器共用同一个应用目录，显式有效包名优先。不要复制零售手机应用别名作为板端目录。
- 用 `snapshot_display` 等实际能力截图，读回图片字节并解码核实 MIME、尺寸、方向；可缩小传给模型，但点击坐标按真实物理画面换算。沿用 starter 的 0–1000 坐标契约，不能将缩略图像素直接当物理坐标。
- 点击/滑动使用实际 `uitest uiInput` 能力；中文输入先核对设备命令是否保留 UTF-8，正确引用空格、换行、单引号和 `$` 等字符，避免命令注入。替换输入先聚焦、全选、清除，再输入；只有 submit=true 才按回车，避免标题输入后意外提交。
- 手动拼音输入法和自动注入中文是不同问题。设置里提供系统输入法选择入口及可用时的当前输入法名称；系统不提供某接口时给出明确提示。
- 每次动作检查取消状态；结束及时关闭 socket、文件、图像、HTTP 与计时器。截图临时文件按任务隔离并回收。
- 返回助手先尝试公开启动能力；后台启动受限或原连接已经取消时，使用独立、短超时的 Self-HDC 连接返回当前助手包名/Ability。返回失败记录提示，不覆盖原任务终态，也不遗漏其他资源清理。

## 四、任务循环、终态和后台运行

采用“应用目录规划→启动目标→真实截图→多模态决策→结构校验→单个动作→新截图核对”的闭环。支持在同一任务中切换目录内 App。界面/网页/导入资料只是待处理数据，不能覆盖原始用户目标。

模型动作应显式校验：动作白名单、必需字段、坐标范围、目标应用、文本长度。JSON 代码围栏可去除；格式错误最多两次重新生成，失败则停止，不能猜出动作继续执行。保留原 starter 的平面动作结构即可，不要求照搬其他项目的数据结构。

终态区分 success、failed、suspended、cancelled。`done` 只有显式成功状态并有当前画面/文件证据时才能报成功。保存、下载、计算结果必须来自实际观察；命令已受理只应显示“已执行，待核对”。最终回复包含可核对结果；正在运行时展示当前阶段、步数和耗时，日志默认折叠。

提供停止按钮。取消应立即结束模型等待，即使底层 destroy 不回调也不能一直挂起。取消后到达的模型响应不得再发新动作。失败、超时后都恢复输入；旧任务的迟到清理不能污染新任务。

建议单次模型请求上限 90 秒、任务上限 10 分钟、动作上限 15 步，允许按复杂度显式调整。最后一个动作执行后仍要再截图确认，不能一到上限就漏掉最后结果；最终观察不得继续执行新动作，未确认完成则 suspended。

跨 App 后助手进入后台，必须适配 API 18 的后台能力。可以申请合规的持续后台任务，失败时回退系统实际授予的短时额度；额度不足或到期暂停。不能保留仅 120 秒的外层期限却宣称支持 10 分钟任务。API 20 起的额度诊断接口必须移除、做兼容适配或降级，不能假定编译成功就可在 API 18 调用。API 不存在、许可不足、拒绝申请都应可诊断。所有终态均释放后台资源。
